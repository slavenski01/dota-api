# Необходимые данные и их смысл

Это аналитический контракт: сведения могут поступать в любом техническом формате. Названия ниже служат обозначениями, а не требованиями к стеку или таблицам базы.

## Параметры задачи

| Параметр | Когда нужен |
| --- | --- |
| Профиль либо выбранный участник | Для персональных выводов; при одном match_id нужно отдельно выбрать игрока |
| Матч, список матчей или период | Для границ анализа и воспроизводимости |
| Подтверждённая позиция | Для ролевых сравнений; неизвестная роль не мешает базовой сводке |
| Герой и аспект при наличии | Для сравнений таймингов, сборок и задач героя |
| Патч и режим | Для сопоставимой базы; не смешивать Turbo и обычную игру |
| MMR или категория ранга с датой и происхождением | Для ранговых сравнений; точный рейтинг не предполагать по категории |
| Состав группы и план сборки | Для объяснения различий и более узких сравнений |
| Часовой пояс | Для календарного времени матча; время событий остаётся игровым |

Не сохранять эти параметры как неизменные значения навыка. Не включать в аналитический набор ключи, токены или пароли.

## Уровни отчёта

| Уровень | Минимум данных | Допустимый результат |
| --- | --- | --- |
| Сводка | Выбранный участник, матч, итоговые показатели и контекст | Наблюдаемые результаты и вопросы без вымышленных таймкодов |
| События | Подходящие временные ряды или журналы с известным покрытием | Кандидаты на просмотр по отдельным применимым правилам |
| Проверка реплея | Фрагмент реплея, контекст и ручная оценка | Подтверждённая ошибка, оправданное действие или неопределённый вывод |

Проверяй возможность каждого расчёта отдельно: подробные покупки не означают доступных смертей или обзора. Обнаруженные положительные события можно описывать в частичном наборе; отсутствие событий в нём нельзя считать доказанным.

## Содержание наборов

| Набор | Обязательный смысл и поля |
| --- | --- |
| Паспорт матча | match_id, начало, длительность, режим, патч при наличии, команды и результат |
| Участник | player_slot в данном матче, сторона, герой, account_id при доступности, роль и источник её определения |
| Итоговая статистика | Отдельные K, D, A; добивания и денаи; GPM и XPM; урон героям и строениям; уровень при наличии |
| Ряд показателя | Игрок, явное игровое время каждого значения, показатель, единица, накопительное или интервальное значение |
| Смерти | Игрок, время, повторные смерти после выкупа; покрытие для обеих команд |
| Предметы | Предмет, тип события, время; отличать покупку, сборку, получение героем и применение |
| Объекты | Тип и идентификатор объекта, время, сторона владельца и сторона, получившая результат, когда применимо |
| Бои | Определение источником боя, начало, конец и участвующие события; полнота и ограничения выделения |
| Контекст реплея | Позиции, обзор команды игрока, готовность ресурсов, продолжение союзников, известные противники |
| Ручная проверка | Эпизод, решение, объяснение, доступная альтернатива, автор и дата |

Идентификаторы хранить в передаче без потери точности. Не связывать скрытые аккаунты по нику. Если account_id скрыт, выбор через player_slot допустим только при отдельном подтверждении соответствия игроку.

## Происхождение и покрытие

Для каждой группы данных нужны источник, время получения, единицы, точность времени и известные пропуски. Статусы: подтверждено присутствует, подтверждённо пусто на указанном окне, отсутствует, ошибка получения, смысл неизвестен. Ноль — значение, а не статус отсутствия.

Для правил, зависящих от отсутствия событий, требуется подтверждённое покрытие всех необходимых участников и всего проверяемого окна. Пустой массив, HTTP 200 или общий флаг «parsed» этого не гарантируют. Обоснование покрытия может опираться на проверенный контракт поставщика и сверку журналов с итоговыми счётчиками; одних совпавших счётчиков недостаточно, если непонятны типы событий и временная ось. При неизвестном покрытии правило пропустить.

Если источники конфликтуют, показать конфликт и отложить зависимый вывод. Не выбирать удобное значение молча. Любая производная метрика должна быть связана с исходными значениями, формулой, фильтрами выборки и конфигурацией правила.

## Время и значения

- Время эпизодов — секунды игрового отсчёта. Отрицательное время до начала игры сохранять. Не смешивать игровое и календарное время.
- Индекс массива сам по себе не является минутой. Требуется временная ось или проверенный контракт её восстановления.
- На 5-й и 10-й минутах предпочтительно точное наблюдение. При разрешённой дискретизации брать последнее наблюдение не позже целевого времени с отставанием не более одного подтверждённого интервала; показывать его фактическое время. Не подставлять более поздний снимок и не экстраполировать.
- Не смешивать заработанное золото, текущее золото и стоимость имущества. В частности, gold_t не называть net worth без подтверждения семантики.
- Время покупки предмета не равно времени доставки герою. Компонент и рецепт не приравнивать к готовому предмету без подтверждённой логики сборки.
- Командные преимущества привести к стороне анализируемого игрока. Если исходное значение равно Radiant минус Dire, для игрока Dire изменить знак.
- Для долей фиксировать знаменатель. Деление на ноль или неизвестный знаменатель означает неопределённую метрику.
- События за пределами известного покрытия не достраивать. Учитывать начало и конец матча при запросе окон просмотра.

## Минимум для правил

| Правило | Необходимые данные |
| --- | --- |
| D01 | Смерть игрока и полный журнал смертей обеих команд на окне t − 15…t + 30 секунд |
| D02 | Смерть игрока и подтверждённое последующее событие потери объекта с правильными сторонами |
| L01 | Снимок линии на 10-й минуте и минимум 10 предыдущих сопоставимых матчей |
| I01 | Выбранный ключевой предмет и надёжное время покупки; известные последующие события |
| F01 | Подтверждённые границы боя и полные потери обеих команд; покрытие объектов для утверждения об их отсутствии |

Полные определения находятся в [аналитических правилах](analysis-rules.md). Если набора не хватает, перечисли точный недостающий тип сведений, не проси все возможные данные сразу.
