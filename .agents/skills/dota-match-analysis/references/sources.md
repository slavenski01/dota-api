# Карта источников

Выбирай источник под аналитический вопрос, а не под наличие API-ключа. Источник и время получения указываются для набора данных; при смешивании провайдеров происхождение сохраняется для каждого показателя.

## Источники по назначению

| Источник | Что из него брать | Что он не подтверждает сам по себе |
| --- | --- | --- |
| Steam Web API | Историю, идентификаторы и базовую сводку завершённых матчей: участники, результат, длительность, итоговые показатели | Причины решений, доступный игроку обзор и подробную хронологию всех действий |
| OpenDota | Доступные результаты разбора: временные ряды, покупки, смерти, бои, объекты | Что каждый матч разобран полностью и все журналы пригодны для вывода об отсутствии событий |
| Реплей в клиенте Dota 2 | Контекст позиции, обзора, доступности продолжения атаки, способностей и предметов | Что просмотр с полной картой соответствует информации игрока в момент решения |
| Ручная разметка | Роль, соперник на линии, план сборки, намерение, оценка эпизода и альтернатива | Независимую объективную причину исхода; разметка тоже может быть неопределённой |
| Уже собранные файлы или данные приложения | Любую из этих категорий, если известны их смысл и происхождение | Смысл полей только по совпадению названий |

OpenDota объединяет Web API Valve и разбор реплеев, поэтому базовая сводка и подробный разбор имеют разную доступность. [Описание OpenDota](https://github.com/odota/core#overview).

## Ориентиры для технической части

Это карта получения данных, а не реализация загрузчика.

| Метод Steam | Аналитическое назначение |
| --- | --- |
| ISteamUser / GetPlayerSummaries v2 | Проверить соответствие выбранного Steam-профиля |
| IDOTA2Match_570 / GetMatchHistory v1 | Найти доступные матчи игрока, получить match_id и match_seq_num |
| IDOTA2Match_570 / GetMatchDetails v1 | Получить сводку конкретного матча при работоспособности метода |
| IDOTA2Match_570 / GetMatchHistoryBySequenceNum v1 | Альтернативный источник сводки по известному номеру последовательности |
| IEconDOTA2_570 / GetHeroes v1 | Расшифровать идентификаторы героев |

GetMatchHistory принимает Dota account_id; SteamID64 — другой идентификатор. Для обычного индивидуального Steam-аккаунта преобразование account_id = SteamID64 − 76561197960265728. Не применять формулу к произвольным числам или идентификаторам групп. После преобразования проверять соответствие выбранному участнику.

Два идентификатора матча, match_id и match_seq_num, не взаимозаменяемы. Для ответа по последовательности обязательно проверить точное совпадение match_id и выбранного игрока. Нельзя анализировать «ближайшую» запись как запрошенный матч. Номер последовательности брать из подтверждённой истории или имеющихся данных; не вычислять его из match_id.

В октябре 2026 года резервный метод успешно вернул сводку при HTTP 500 от GetMatchDetails. Это наблюдение ограничено проведёнными проверками; подробности — в [журнале наблюдений](session-observations.md). Наблюдение не требует всегда обходить GetMatchDetails и не гарантирует будущую доступность альтернативы.

## Как формулировать запрос данных

Для сводки одного матча запроси выбранного участника, идентификатор матча, сторону, результат, длительность и итоговые показатели. Для персонального эпизода укажи конкретное правило и недостающий журнал: например, D01 требует покрытие смертей всех десяти игроков вокруг каждой рассматриваемой смерти.

Для серии попроси контекст сопоставимости по каждому матчу и историю того же показателя. Для неизвестной роли можно подготовить факты, но не ролевую оценку. Для проверки причины нужны отмеченные фрагменты реплея и сведения об информации, доступной игроку.

Не обещай всю историю аккаунта по total_results одной выдачи. Открытый Steam-профиль сам по себе не доказывает доступность истории Dota 2. Наличие API-ключа не отменяет настройки приватности. Отсутствующий старый реплей может сделать событийный анализ невозможным.

## Первичные ориентиры

- [Steam Web API](https://partner.steamgames.com/doc/webapi_overview) — общая структура официального API.
- [Документация OpenDota](https://docs.opendota.com/) — контракт стороннего API.
- [Типы OpenDota](https://github.com/odota/core/blob/master/global.d.ts) — различие базовых и разобранных данных.
- [Схема OpenDota](https://github.com/odota/core/blob/master/sql/create_tables.sql) — вспомогательный ориентир, не гарантия структуры API-ответа.

Ссылки на master меняются. При новом аналитическом контракте отмечать дату проверки или версию источника. Не выдавать список полей из справочника за результат запроса конкретного матча.
