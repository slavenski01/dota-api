# Сравнение собственных матчей E09

Из карточки обработанного матча откройте «Сравнить с предыдущими играми».
Подтвердите позицию, патч и при необходимости аспект, группу и план игры.
Автор и дата подтверждения сохраняются; исправления создают следующую версию.
Для базы типичных полных игр отдельно подтвердите отсутствие преждевременного
ухода участника и существенных разрывов. Неизвестные сведения остаются неизвестными.

По умолчанию совпадают герой, подтверждённая позиция, патч и режим. Расширение
каждого условия требует явного переключателя, выбранные условия видны рядом
с результатом. Текущий матч, будущие игры, другие игроки, конфликты, непроверенные
наборы, уходы и разрывы исключаются с указанием причины. Победы и поражения
включаются одинаково. Список ограничен 1000 сохранёнными играми; превышение явно
показывается. История источника может быть неполной.

Каждая метрика имеет собственный n, медиану, Q1/Q3 с линейной интерполяцией
и диапазон. Итоговые счётчики зависят от длительности и обстоятельств игры;
это описательные значения, не рейтинг качества решений.

Миграция 017 добавляет comparison_contexts и comparison_runs. Снимок содержит
точные datasetId, версии контекста, входные числа, ссылки на evidence и фильтры.
Выборка читается в транзакции REPEATABLE READ, идентификатор определяется хешем
входов. Повтор запроса идемпотентен; исправление контекста не меняет старый снимок.
В API нет произвольного SQL или входа для подтверждения покрытия источника.

GET /api/datasets/:id/comparisons?accountId=… возвращает до 50 последних снимков
и историю контекста. POST с action=context сохраняет контекст с expectedVersion;
action=compare создаёт снимок с relaxed/additional. Проверяются участник набора,
Origin, форма и размер запроса. Конкурирующее изменение контекста возвращает 409.

Проверки: npm run test:comparisons, npm run typecheck и production build web.
