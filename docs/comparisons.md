# Сравнение собственных матчей E09

Из карточки обработанного матча откройте «Сравнить с предыдущими играми».
Подтвердите позицию, патч и при необходимости аспект, группу и план игры.
Автор и дата подтверждения сохраняются; исправления создают следующую версию.
Для базы типичных полных игр отдельно подтвердите отсутствие преждевременного
ухода участника и существенных разрывов. Неизвестные сведения остаются неизвестными.

По умолчанию совпадают герой, подтверждённая позиция, патч и режим. Расширение
каждого условия требует явного переключателя, выбранные условия видны рядом
с результатом. Текущий матч, будущие игры, другие игроки, конфликты, непроверенные
наборы, уходы и разрывы исключаются с указанием причины. Победы и поражения
включаются одинаково. Список ограничен 1000 сохранёнными играми; превышение явно
показывается. История источника может быть неполной.

Каждая метрика имеет собственный n, медиану, Q1/Q3 с линейной интерполяцией
и диапазон. Итоговые счётчики зависят от длительности и обстоятельств игры;
это описательные значения, не рейтинг качества решений.

Миграция 017 добавляет comparison_contexts и comparison_runs. Снимок содержит
точные datasetId, версии контекста, входные числа, ссылки на evidence и фильтры.
Выборка читается в транзакции REPEATABLE READ, идентификатор определяется хешем
входов. Повтор запроса идемпотентен; исправление контекста не меняет старый снимок.
В API нет произвольного SQL или входа для подтверждения покрытия источника.

GET /api/datasets/:id/comparisons?accountId=… возвращает до 50 последних снимков
и историю контекста. POST с action=context сохраняет контекст с expectedVersion;
action=compare создаёт снимок с relaxed/additional. Проверяются участник набора,
Origin, форма и размер запроса. Конкурирующее изменение контекста возвращает 409.

Проверки: npm run test:comparisons, npm run typecheck и production build web.

## Линия к десятой минуте

Новые разборы сохраняют optional HeroState.lane (lane-v1): наблюдения счётчиков
m_iLastHitCount и m_iTotalEarnedXP из CDOTA_DataRadiant/CDOTA_DataDire, отдельно
для каждого игрока. Проверяются неотрицательность, монотонность и согласованность
с финальным счётчиком. XP сверяется с точным счётчиком; округлённый XPM не
используется для восстановления опыта. Игровое время учитывает паузы. Момент
600 с берётся точно либо по последнему наблюдению не старше 5 с; более поздние
снимки, интерполяция и итоговые числа не подставляются. Фактическое время видно.
Старые наборы остаются без lane; нужны повторный разбор и новое сравнение.

L01 считает отдельный n для добиваний и опыта. Минимум — 10 предыдущих значений;
сигнал строго ниже Q1. При неизвестном контексте, ослабленных фильтрах, непроверенном
текущем матче или Q1=Q3 сигнал отключён. Сохранённая выборка включает точные
значения, времена и evidence каждого матча. Без достаточной базы показываются
доступные факты и причины пропуска.

Сравнение создаёт новую версию детерминированного анализа, если исходный анализ
уже готов. L01 использует известные смерти до 600 с либо обзор 0–600 с; время
ошибки не выдумывается. Старые эпизоды/оценки/отчёты не изменяются. Тренер на
странице сравнения получает эти факты и ссылку на неизменяемую базу, только по
отдельному нажатию. Подтверждённая роль согласуется с ролью выборки.

Проверки E09-T02: 3 сценария L01 (включая БД → эпизод → контекст тренера),
2 сценария выборок. Контрольный реальный реплей успешно проверен: у всех десяти
участников доступны оба снимка в [595,600], числа не превышают финальные счётчики.
Это подтверждает контрольный реплей, не любую будущую запись. Реальной базы
из десяти сопоставимых матчей пока нет; положительный сигнал проверен на
явно синтетической выборке. Регрессии контрактов, метрик, маскирования, эпизодов
и тренера, Kotlin build/test и web build пройдены.
