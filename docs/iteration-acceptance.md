# Приёмка итерации E13–E15

18 октября 2026 года. **M4a, M4b и M4 приняты** в описанных границах.
E13, E14, E08 и E15 завершены. Это техническая приёмка функций и сохранности,
а не подтверждение игровых ошибок или эффективности обучения.

## Проверенная среда

macOS arm64, Colima `dota-api` (4 CPU / 8 GiB), Docker Compose, production
Next.js 16.4.0 / React 19.3.0, Node 26.3.0, PostgreSQL 18.6. Парсер:
Kotlin 2.4.20 / Clarity 5.0.1; форматы `coach-v1`, `playback-v1`, `motion-v1`.
Рабочий сервис — `127.0.0.1:3002`, миграции включают 016.
AI — сохранённые отчёты Codex CLI 0.162.0-alpha.17.2, gpt-6-astra/medium.

## Реальные контрольные матчи

Повторно использованы все три отчёта E08-T04 и четвёртый уже готовый отчёт.
Три разных матча с рекомендациями прошли путь: готовый разбор → точная версия
отчёта → эпизод → воспроизведение → заметка/оценка → исходный отчёт → перезапуск.
В браузере проверены выбранный герой, точное время, перезагрузка ссылки и возврат.
Два набора имеют прежние редкие состояния, один — координаты раз в 250 мс.
Четвёртый матч с недостаточным покрытием корректно показывает сводку и
эксперимент без выдуманных эпизодов; доступен полный просмотр и обычная заметка.

| Контроль | Данные и результат | Сохранённое время AI | Входные / выходные токены |
| --- | --- | --- | --- |

Для E15 выполнено **0 новых вызовов модели**. Сумма сохранённого usage четырёх
отчётов: 112 141 входной и 1 533 выходных токена. Денежная стоимость не известна
(`null`), используется подписка; это не утверждение о бесплатном расходе.
Качественная оценка исходных трёх текстов описана в [E08-T04](coach-quality.md).
E15 проверяет основания рекомендаций по исходным записям и хешам, не повышая
гипотезы до установленных причин или ошибок.

Оставлены явно помеченные технические заметки и оценки «Неопределённо» с автором
«Codex — техническая приёмка E15». Они не выдают проверку программы за игровой
разбор пользователя. Существующие оценки не заменялись; повторное сохранение
через браузер добавило ещё одну версию. Старые отчёты помечены устаревшими,
их контексты и тексты остались неизменными. Новая генерация после изменения
оценки проверена с контролируемым провайдером в HTTP-тесте.

## Карта, плавность и отказы

- Локально проверены все 127 PNG по пикселям, размерам, именам и SHA-256.
  Браузерный стенд подтвердил заглушки для героя 9999 и HTTP 404 иконки.
- При перемотке и HTTP 503 подложка остаётся; кнопка повтора восстанавливает
  кадр. При неизвестной позиции остаются девять маркеров и явное «неизвестно»,
  десятый герой не дорисовывается. Тесты сглаживания покрывают скачки, смерть,
  возрождение, пропуски и неподходящие соседние наблюдения.
- На реальном отрезке около 25 с при 1× штатная диагностика показала
  120,1 rAF/с, максимальный интервал 9,4 мс, 0 мс буферизации. Три HTTP-запроса,
  p95 94,0 мс, 1 306 890 байт получено; кэш — три окна / 1 306 890 байт.
  Это частота браузерных кадров на текущей машине, не частота исходных данных
  и не обещание для любого устройства. Переполнения страницы не обнаружено;
  раскрытые основания дополнительно проверены при ширине 390 px.
- Замеры E14: пять реальных реплеев, 4,18–6,86 с на извлечение движения,
  1,12–2,12 MiB gzip; API читает 30-секундные окна с ограниченным кэшем.
  Полные условия и сравнение частот — [playback.md](playback.md).
- Неверные reportId/datasetId/участник/эпизод и будущий формат дают ошибку без
  подстановки другого набора. Режим команды не получает текст рекомендации,
  evidence, полные состояния или события. Лимиты, таймаут и повторное нажатие
  проверены через управляемые отказы провайдера; искусственно исчерпывать
  реальную подписку не потребовалось. Просмотр от наличия AI не зависит.

заметок, исходных оценок и окон воспроизведения. Затем штатный backup сохранил
dump БД (2 158 920 байт), Storage (344 043 520 байт) и фактический образ
(255 767 040 байт); контрольные суммы проверены.

Восстановление выполнено в **новый** проект `dota-e15-restored`, порт 3015.

Штатный Storage audit проверил артефакты, а HTTP — те же окна воспроизведения
и страницы четырёх матчей. Браузер подтвердил восстановленную заметку,
две версии оценки, выбранного героя и карту. Основной проект снова healthy;
восстановленный остановлен, его volumes сохранены.

Частные снимки, ссылки, скриншот, backup и журнал — в игнорируемом

## Повторение

После сборки и запуска основного проекта:

```sh
export DOCKER_CONTEXT=colima-dota-api
node scripts/coach-viewing-acceptance.mjs capture
# Проверить интерфейс; capture добавляет помеченные технические заметки/оценки.
node scripts/coach-viewing-acceptance.mjs seal
node scripts/coach-viewing-acceptance.mjs verify
node scripts/local.mjs backup data/backups/new-e15-copy
node scripts/local.mjs restore data/backups/new-e15-copy new-e15-restore 3015
node scripts/coach-viewing-acceptance.mjs verify http://127.0.0.1:3015 new-e15-restore
```

Нужны три готовых реальных отчёта с рекомендациями и один контроль без эпизодов.
Harness не создаёт новые AI-задания и не загружает реплеи. `seal` фиксирует хеши
после браузерной проверки; `verify` ничего не записывает в БД. Для повторного
restore нужны свободный порт и новое имя проекта/volumes.

Успешен 21 автоматический сценарий: coach-web/context/provider/quality,
match-notes, episode-reviews/view, playback/visual, explorer-web и backup.
Файлы с PostgreSQL запускались каждый в своей временной БД. Сборки пакетов,
worker, production web, контейнера и typecheck успешны. JVM-код не менялся;
образ использует ранее проверенную сборку парсера. Board и локальные ссылки
проверены при оформлении выпуска.

Ограничения прежние: приблизительная подложка 7.40, неизвестные командный обзор
и cooldown/canUse, частичное покрытие некоторых журналов. E09 и E11 отложены;
следующий эпик автоматически не выбран.
