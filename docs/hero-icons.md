# Герои на карте — E13

Завершено 18 октября 2026 года. Локально доступны **127 героев**, 666851 байт PNG.
Имена, ID и внутренние имена сверены с официальным herolist Valve и OpenDota.
Происхождение каждого файла, SHA-256 и размеры записаны в
[`hero-catalog.json`](../apps/web/lib/hero-catalog.json).
[Уведомление об авторстве и обновление](../apps/web/public/heroes/README.md).

## Поведение

Карта всей игры и карта эпизода используют один `HeroPortrait`. Круглая зелёная
рамка означает Radiant, квадратная персиковая — Dire; белая обводка выделяет
выбранного героя. Умирающий/мёртвый герой сохраняет портрет и получает крест.
Наведение и доступное имя сообщают героя, команду, время наблюдения и смерть.
Tab/Enter/Space доступны для маркеров и списка; при перекрытии выбирайте список.
Кнопки списка имеют минимальную высоту 44 px. Выбор списка и таблицы использует
тот же playerSlot, что карта и панель состояний.

Портрет занимает 32×32 px, маркер с рамкой — 38×38 px. Muerta (32×31 в оригинале)
вписывается без растяжения. При неизвестном ID или ошибке файла показан ID в
заглушке того же размера, полное имя/ID доступны в подписи и списке. Ошибка
запоминается на время документа, чтобы перемотка не создавала повторных запросов;
перезагрузка страницы повторяет попытку. Неподтверждённая позиция не создаёт маркер.
Командная перспектива по-прежнему скрывает неподтверждённые положения.

`HeroPreloads` предварительно загружает уникальные иконки участников. Пути
`/heroes/<id>.<hash>.png` локальные и получают `Cache-Control: public,
max-age=31536000, immutable`; новый файл получает новый URL. Общий каталог
обновляется скриптом без ручных изменений компонентов. Подложка остаётся локальной.

Исчезновение компонента карты во время ожидания кадра пока сохраняется; это E14-T01.
Частота исходных координат, интерполяция и факты анализа в E13 не менялись.

## Проверки

- `npm run check:hero-icons`: 127 уникальных файлов, полное декодирование пикселей,
  формат PNG, размеры, длина, SHA-256, соответствие ключей ID/путей/имён.
- Сборка всех TS-пакетов/worker и production Next.js, `npm run typecheck` успешны.
- `npm run test:episode-view`: две проверки кадров, геометрии, unknown,
  возраста наблюдения и отсутствия раскрытия ретроспективы в decision.
- `npm run test:explorer-web`: production HTTP, проверка PNG байт-в-байт,
  cache headers и 404, прежние сценарии фильтров, заметок и изоляции.
- Браузер: игра и эпизод, 10 правильных портретов, смерть, перекрытие,
  выбор из карты/списка/таблицы, Tab/Enter и 390/1200 px без переполнения страницы.
  В отдельном proxy-origin один PNG намеренно отвечает 404, последний герой —
  неизвестный ID 9999. Обе заглушки сохраняют размер; восемь остальных иконок
  загружаются. После смены героя и перемотки каждый известный URL запрошен ровно
  один раз, включая 404; для ID 9999 запроса нет. Консоль браузера без ошибок JS.

Это проверка представления на синтетических данных, не новая приёмка полноты
реального реплея. Скриншот локально: `data/e13-validation/hero-map.jpg` (вне Git).

Браузерный стенд можно повторить, сначала собрав production web:

```sh
EXPLORER_PREVIEW_GATE=/tmp/dota-e13-preview-finished npm run test:explorer-web
# Открыть напечатанные Explorer/Episode/Icon failure preview URL.
# После проверки создать указанный gate-файл, чтобы завершить тест и очистить БД.
touch /tmp/dota-e13-preview-finished
```

Используйте новое имя gate-файла для каждого запуска. Стенд создаёт временную БД
и отдельный loopback proxy для HTTP 404; рабочие изображения и данные не меняет.
