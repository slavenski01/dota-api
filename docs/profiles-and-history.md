# Профиль и история матчей

## Профиль (E03-T01)

`/profile` позволяет явно выбрать Dota account ID или SteamID64. `POST /api/profile`
принимает `{ "kind": "account" | "steam", "id": "строка" }`; `GET /api/profile`
возвращает `{ profile }`, включая null до первого выбора. SteamID64 разбирается
через BigInt: universe=1, type=1, instance=1. Нулевой и анонимный UINT32_MAX
не выбираются. В ответе ID остаются строками. Ник никогда не служит идентификатором.

Сохранённый выбор общий для локального сервиса, переживает перезапуск и не меняет
принадлежность ранее сохранённых участников. Ответ OpenDota проверяется по ID.
Отсутствие имени/профиля даёт unknown, fh_unavailable=true — limited; эти признаки
не доказывают отсутствие игр. Ошибка источника сохраняет предыдущий выбор.

Сервер обращается к фиксированному HTTPS origin OpenDota, ограничивает ответ 2 MiB
и запрос 15 секундами. Ошибки API, сети, JSON и 429 не превращаются в пустой профиль.
Retry-After возвращается клиенту. API не требует ключа. Аватар допускается только
по HTTPS с доменов Steam. Проверенный контракт источника: https://api.opendota.com/api
(13 октября 2026). Личные данные и реальные ответы не коммитятся.

Проверка: `npm run test:profiles` — отдельная временная PostgreSQL; синтетические
ответы источника проверяют точность, неверные ID, идентичность, смену профиля и сбои.

## История (E03-T02)

`POST /api/history` принимает `{accountId, mode: "refresh" | "older"}`.
Возвращает 202 с id задания или 200 с cached=true. `GET /api/history?accountId=…`
возвращает страницы, следующий offset, признак конца доступной выдачи и последнее
задание. Обновление не происходит при чтении и не запускается по расписанию.
Нужен запущенный worker. Задания идут через существующую ограниченную очередь
pg-boss; создание задания и запись запроса транзакционны. Дубли активного запроса
объединяются. Запись страницы и завершение очереди проверяют владение попыткой.
Потерянное/отменённое задание можно повторить вручную.

Один запрос получает не более 50 записей OpenDota, `significant=0`, `sort=start_time`.
Refresh читает offset=0, older — следующую страницу. Успешная страница кэшируется
60 секунд; повторный refresh в этот интервал не обращается к источнику. Матчи
обновляются по паре account_id/match_id, существующая история не удаляется.
Неизвестные K/D/A и результат сохраняются как null, а не как ноль/поражение.
Конфликт личности участника отклоняет всю страницу. Сохранённые данные связываются
с ID запроса, даже если пользователь в это время выбрал другой профиль.

Короткая страница означает конец текущей доступной выдачи, а не всю историю игрока.
Offset источника может сдвигаться при новых играх; дедупликация устраняет повторы,
но не доказывает полноту. Пустая страница — успешный ответ, ошибка — отдельное
состояние с сохранением старых данных. HTTP 429 сохраняет Retry-After в PostgreSQL
и блокирует новые запросы истории до этого времени. Автоматический цикл повторов
ошибок источника не создаётся; повтор запускает пользователь. Сетевые таймауты,
невалидный ответ и ограничение доступа имеют разные коды.

`npm run test:history`: 6 сценариев на реальных PostgreSQL/pg-boss с синтетическим
HTTP-источником: страницы/кэш/дубли, обновление, пустой ответ и ошибки, 429,
атомарность конфликта личности, восстановление после отмены задания.
