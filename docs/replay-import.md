# Получение и импорт реплея

## Поиск источника (E04-T01)

`resolveReplay` сначала проверяет SHA-256 и размер сохранённого артефакта с
маркером `replay-v1`. Произвольный артефакт или ссылка не доказывают наличие
реплея. При проверке игрока требуется его ID в проверенных метаданных файла.

OpenDota `/matches/{id}` проверяется на совпадение ID и, если задан, участника.
URL допускает только HTTP/HTTPS `replay{cluster}.valve.net/570/{match}_{salt}.dem`
с необязательным `.bz2`/`.zst`. Запрещены порты, credentials, query и fragment.
Каждый redirect проверяется до запроса, максимум три перехода.

В `dota.replay_sources` сохраняются источник, время и серверный URL-кандидат.
Кандидат кешируется на пять минут; `force` обновляет его. При запросе с игроком
кеш подходит только для ранее проверенного участника. HEAD 404/410 означает
`unavailable`, отсутствие ссылки — `missing`, сетевые ошибки/прочие HTTP —
временную ошибку. HEAD 405 допускает дальнейшую проверку GET. Даже HEAD 200
не подтверждает корректность содержимого. Отрицательные ответы не кешируются
для последующих попыток. URL не возвращается в публичное состояние задания.

Проверки: `npm run test:replay-source` — PostgreSQL, ответы провайдера и CDN
заменены контролируемыми ответами; реальные реплеи исследованы в E01.

## Скачивание и проверка (E04-T02)

`downloadReplay` повторно получает метаданные после GET 403/404/410 (один раз).
`importReplay` — общий потоковый путь для скачивания и ручного файла. Вход
временно сохраняется в приватном каталоге ОС; декодер определяется по первым
байтам. Поддержаны Source 2 `.dem`, Zstandard через Node.js и bzip2 через
системный `bzip2`. Для bzip2 нужен исполняемый файл в PATH. Ошибка распаковки,
обрыв, неожиданный формат или превышение лимита не публикуют артефакт.

Пределы: вход 256 MiB, распакованный файл 1 GiB, получение/распаковка 180 секунд,
Clarity 120 секунд, JVM heap 1 GiB, RSS процесса 1.5 GiB (надзор E02).
Проверяются Content-Length при наличии, SHA-256, заголовок, полный успешный
NDJSON до EOF и exit code 0, соответствие хеша в provenance, match ID,
десять уникальных слотов и единственное совпадение выбранного account ID.
Полный базовый проход Clarity подтверждает Stop/FileInfo, но не означает
готовность расширенных данных E05 или анализа E08.

Только после проверки файл атомарно помещается в content-addressed Storage;
регистрация в БД выполняется вызывающим workflow в его транзакции. Отмена
и ошибка очищают временные файлы. Падение процесса может оставить временный
каталог ОС `dota-replay-*`; его можно удалить после остановки worker. Не
зарегистрированные в БД blob не доступны через пользовательский API.

Прогресс содержит фактически полученные/распакованные байты. Общий размер
при отсутствии Content-Length неизвестен; процент в этом случае не вычисляется.
Результат содержит способ сжатия, время получения и подтверждённых участников;
исходный CDN URL остаётся только в серверном кеше источника.

`npm run test:replay-import` проверяет три декодера, повреждения/обрыв, лимиты,
отмену, обновление URL и локальное переиспользование. Если локальные материалы
E01 доступны, дополнительно выполняет настоящий Clarity на образце и отрицательные
проверки идентичности; в чистом checkout этот отдельный тест явно пропускается.

## Интерфейс и задания (E04-T03)

В `/profile` действие «Загрузить и разобрать» ставит одно устойчивое задание
и открывает `/matches/{id}?accountId={id}`. Карточка показывает сохранённую
статистику, этап, ошибки, повтор и отмену. Reload восстанавливает последнее
задание этого матча/игрока из БД. Account ID фиксируется при запуске.
Повторное нажатие во время обработки возвращает то же активное задание.

Ручной файл отправляется потоковым POST `/api/replays/{id}?accountId=...`
с Content-Type `application/octet-stream`, без multipart и загрузки в память.
Браузер показывает реально отправленные байты. Непроверенный вход регистрируется
отдельным `application/x-dota-upload` и обрабатывается очередью. Он не считается
реплеем и не выдаётся пользователю. Входы сохраняются для повторной обработки;
автоматическая сборка неиспользуемых blob/импортов пока не реализована.
Одновременный запрос импорта при активной обработке возвращает существующее
задание; новый вход не заменяет вход активного задания.

GET `/api/replays/{id}` возвращает сводку, последнее задание и размер сохранённого
проверенного реплея, без путей/URL источника. GET `/api/replays/{id}/file`
повторно проверяет размер, хеш и наличие выбранного участника, затем потоково
выдаёт `.dem` как attachment. Произвольный artifact ID не является файловым API.

Workflow использует прежние состояния: после сохранения файла завершает
дальнейшую обработку `unavailable / analysis_not_connected`. Это означает
отсутствие расширенного анализа E05–E08, а не отсутствие файла. В карточке
отдельно показано «Реплей сохранён» и доступно скачивание. Статистика из истории
сохраняет `dataLevel=summary`; извлечение E04 не публикует dataset E05.

Web и worker одинаково разрешают относительный STORAGE_ROOT от корня проекта.
Перед запуском нужен `npm run build:parser` и системный bzip2. Миграции 006/007
применяются штатным `db:migrate`. Zstandard ограничен окном 128 MiB, результатом
1 GiB и временем потока; bzip2 работает в отдельном процессе и прерывается
при отмене, ошибке потока или превышении лимита.

Проверки E04-T03: `npm run test:replay-web`, production HTTP + PostgreSQL +
настоящий Clarity на локальном образце E01, повторное использование, SHA-256
скачанного файла, недоступный источник, недопустимый файл и проверка Origin.
Браузерная проверка: запуск из истории, переход в карточку, reload и сохранённая
статистика при недоступном реплее. Реальные CDN/OpenDota в автоматических тестах
заменены контролируемыми ответами; это не проверка текущей доступности внешнего API.
