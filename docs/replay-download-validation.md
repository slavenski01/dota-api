# Проверка получения контрольных реплеев

Дата: 12 октября 2026 года. Задача: E01-T02. Статус: DONE.

Получены и распакованы **пять из пяти** выбранных реплеев по цепочке профиль → история OpenDota → метаданные матча → URL Valve → файл. Для каждого match_id и SteamID выбранного участника прочитаны из содержимого `.dem` и сверены с исходными данными. Ручные файлы не использовались. Это проверка получения и идентификации файлов; события, состояния и совместимость Kotlin/Clarity ещё не проверены.

Публичный отчёт обезличен по решению пользователя. Образцы обозначены R1–R5; соответствие match_id, исходные URL, сведения об участнике, точные размеры и SHA-256 находятся только в локальном `data/replay-validation/2026-10-12-e01-t02/manifest.json`. Реплеи и исходные ответы исключены из Git.

## 1. Источники и выполненная цепочка

1. Взята проверенная история выбранного профиля из [E01-T01](data-source-validation.md). Её исходный снимок и профиль доступны локально в `data/source-validation/2026-10-12-e01-t01/`.
2. Повторно запрошены пять `/matches/{match_id}` OpenDota: HTTP 200 каждый. Перед использованием ссылки проверены точный match_id и единственность выбранного account_id в участниках.
3. Полученные URL имели вид `http://replay{cluster}.valve.net/570/{match_id}_{salt}.dem.bz2`. Проверены домен, путь и соответствие ID. HEAD каждого адреса вернул HTTP 200 и Content-Length.
4. Пять GET завершились HTTP 200, код curl 0; перенаправлений не было. Скачивание шло в `.part`. Фактический размер совпал с Content-Length и размером, зафиксированным curl; MD5 совпал с заголовком `X-Goog-Hash`.
5. Формат определён по сигнатуре, выполнены потоковая распаковка и SHA-256 архива/результата. Для `.dem` проверены заголовок Source 2, границы записи метаданных, внутренние match_id и участник. Окончательные имена `.dem` присвоены только после проверки идентичности.

Использованы HTTP-ссылки, возвращённые API; HTTPS для этих файлов не проверялся. Совпадение MD5 — проверка согласованности передачи с полученным заголовком, не независимое доказательство подлинности источника. Время получения записано отдельно от HTTP Date: ответы CDN могут содержать старую дату и Age.

## 2. Фактический формат: Zstandard под расширением .bz2

У всех пяти файлов первые четыре байта — `28 b5 2f fd`, сигнатура Zstandard; сигнатуры bzip2 `BZh` нет. Первоначальная проверка ожидаемого bzip2 остановилась на несовпадении сигнатуры; это не было объявлено повреждением реплея. Успешная распаковка выполнена встроенным `node:zlib.createZstdDecompress()` на Node.js **26.3.0**, Zstandard **1.5.7**. Локальные архивы названы `R1.dem.zst` … `R5.dem.zst`; исходные URL сохранены без изменения.

Основания: [сигнатура Zstandard в RFC 8878](https://www.rfc-editor.org/rfc/rfc8878.html#section-3.1.1) и [API Node.js для распаковки Zstandard](https://nodejs.org/api/zlib.html#zlibcreatezstddecompressoptions). Это наблюдение пяти файлов, не утверждение о формате всех реплеев Valve.

Следствие для E04-T02: выбирать декодер по содержимому и поддерживать проверенные варианты, а не доверять суффиксу URL или одному Content-Type. Bzip2 в этой выборке не встречался; его обработка не считается проверенной. В `.gitignore` добавлено исключение `*.dem.zst`.

## 3. Размеры и время

MiB = 1 048 576 байт. Время скачивания — `curl time_total`, включая сеть и прокси; пять загрузок выполнялись одновременно. Время распаковки включает потоковый подсчёт SHA-256/MD5 и запись файла. Это единичные замеры на текущей машине, не норматив производительности.

| R1 | 42.58 | 73.47 | 10.265 | 0.191 | Совпали |
| R2 | 34.56 | 59.10 | 6.872 | 0.137 | Совпали |

Суммарно: около **230 MB архивов + 393 MB распакованных данных**, около 623 MB на диске без малых файлов диагностики. Для всех десяти файлов вычислен SHA-256, затем повторно прочитан весь файл и сверена контрольная сумма; пять `.dem` имеют разные хеши.

Для исследовательского запуска заданы ограничители: 256 MiB входа, 1 GiB распакованного результата, 180 с на загрузку, 15 с на соединение, прекращение при скорости менее 1 KiB/с в течение 30 с, 1 MiB для записи метаданных. Ни один предел не достигнут. Эти значения ограничивали данный эксперимент; лимиты приложения, память и параллелизм парсера выбираются после E01-T03.

## 4. Проверка содержимого .dem

У каждого результата сигнатура `PBDEMS2\0`. Из 4-байтового little-endian поля по смещению 8 прочитана позиция конечной записи; она находится внутри файла. Заголовок первого пакета начинается после 16-байтового префикса. Тип конечной записи — `DEM_FileInfo=2`; установлен флаг сжатия Source 2 `64`, полезная нагрузка Snappy полностью декодирована. Границы записи точно совпали с концом файла.

Одноразовая ограниченная проверка прочитала protobuf-поля `CDemoFileInfo.game_info` → `CGameInfo.dota` → `match_id`, а также `player_info.steamid`. Все пять match_id совпали с запросом, в каждом найден ровно один выбранный SteamID среди десяти участников. Герой, команда, game_mode и game_winner также совпали с ответом OpenDota. Отдельно заголовок подтвердил игру Dota. Имя файла не использовалось как доказательство внутреннего ID.

Проверка опиралась на [EngineMagic Clarity](https://github.com/skadistats/clarity/blob/master/src/main/java/skadistats/clarity/model/EngineMagic.java), [чтение пакетов Source 2](https://github.com/skadistats/clarity/blob/master/src/main/java/skadistats/clarity/model/engine/PacketInstanceReaderProtobufDemo.java), [схему Dota demo.proto](https://github.com/SteamTracking/Protobufs/blob/master/dota2/demo.proto) и [описание формата Snappy](https://github.com/google/snappy/blob/main/format_description.txt). Снимки схемы и описания Snappy сохранены локально с SHA-256. Это узкая проверка метаданных исследовательскими командами; Clarity в проект не подключался.

`playback_time` и тики из метаданных сохранены отдельно и не приравниваются к `duration` OpenDota или игровому времени. Восстановление временной оси, пауз и событий относится к E01-T03. Успешное чтение метаданных не доказывает правильность разбора всех пакетов, смертей, способностей или обзора.

## 6. Артефакты и следующий шаг

В `data/replay-validation/2026-10-12-e01-t02/` находятся:

- `manifest.json` — итоговые соответствия, происхождение, размеры, замеры, хеши, результаты проверки и ссылки на исходные профиль/историю;
- `candidates.json`, ответы OpenDota, заголовки и метаданные HEAD/GET — путь от истории к каждому URL;
- `R1.dem.zst` … `R5.dem.zst`, `R1.dem` … `R5.dem` — оригинальные архивы и проверенные результаты;
- `R1.fileinfo.json` … `R5.fileinfo.json` — извлечённые метаданные с точными ID;
- `downloads.json` — промежуточные замеры распаковки; окончательные пути и статус берутся из manifest.json;
- `demo.proto`, `snappy-format.txt` — использованные справочные снимки.

Для повторения сначала обновить `/matches/{match_id}` по локальному списку кандидатов, заново проверить участника и ссылку, сохранить результат в новую папку. Проверить HTTP, размер, сигнатуру сжатия, полностью распаковать с ограничением результата, сохранить хеши и сверить ID из содержимого. Существующие образцы не перезаписывать. Готового загрузчика сервиса и команды приложения для этой цепочки пока нет.
