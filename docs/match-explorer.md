# Самостоятельное изучение всей игры (E12)

E12 расширяет просмотр с окон эпизодов на весь проверенный набор. AI-тренер E08 и сравнения E09 отложены после MVP. Эпизоды и ручные оценки остаются доступными.

## API

`GET /api/datasets/:datasetId/explore?accountId=…&resource=match|frame|events|series`.
Набор и выбранный аккаунт проверяются для каждого запроса; наличие анализа/эпизодов не требуется.

- `match` (по умолчанию): паспорт, десять участников, статистика, покрытие и границы времени. Границы включают отрицательное время, подтверждённое покрытие часов и доступные записи.
- `frame&time=…&mode=retrospective|decision`: последние состояния не позже выбранного времени, возрастом до пяти секунд. Равные по времени конфликтующие наблюдения дают пропуск. Карта использует прежнюю проверку координат и приблизительную подложку 7.40.
- `events&mode=…`: журнал с `type=death|item|objective|fight`, `playerSlot`, `limit` (1–200, по умолчанию 100), `cursor`. Курсор привязан к набору и фильтрам; порядок `(game_time_seconds, id COLLATE C)` не теряет события с равным временем. Для героя выбираются только явно связанные участники, командный объект ему не приписывается.
- `series&playerSlot=…&mode=…`: доступные HP/мана с реальными временами и evidence-ID. Нули сохраняются, неизвестные/устаревшие/конфликтующие значения — null. Золото/опыт/добивания во времени пока не извлекаются.

В `decision` состояния неизвестны, события и графики пусты; сегменты полного обзора не читаются. Паспорт и итоговая статистика — отдельные ретроспективные данные, не информация игрока в момент решения. Командный обзор, smoke/обнаружение и готовность способностей не подтверждены.

`npm run test:match-explorer` проверяет серверные запросы на временной PostgreSQL и синтетических данных, включая отсутствие анализа, границы времени, чужой аккаунт, пагинацию и маскирование. Это не свидетельство полноты реального реплея.

## Экран и заметки

Карточка разобранного матча содержит «Исследовать всю игру». Адрес
`/matches/:matchId/explore?accountId=…&datasetId=…&time=…&hero=…&mode=retrospective`
сохраняет набор, время, героя и перспективу; `eventType`, `eventPlayer`, `cursor`
сохраняют журнал. Перезагрузка восстанавливает параметры. Таймлайн охватывает
всю запись, стрелки меняют время на секунду. Старые ответы при смене параметров
скрываются, запросы отменяются. Таблица итогов и графики HP/маны доступны в
ретроспективном режиме; карта и состояния синхронизированы.

`GET /api/datasets/:id/notes?accountId=…&mode=…` возвращает собственные заметки
только этого набора и перспективы. POST с `accountId` принимает `id` (UUID v4),
`time`, `playerSlot`, `mode`, `content` (1–2000 символов). Сервер проверяет аккаунт,
время, героя, Origin и размер тела; ставит дату. Таблица `match_notes` неизменяема.
Повтор идентичного запроса возвращает ту же заметку, иной ввод с тем же ID — 409,
включая конкурентные запросы. Текст выводится средствами React без HTML.
Заметка не создаёт оценку ошибки и не переносится на новый набор после перепарсинга.

Проверки E12-T02/T03: TypeScript, production-сборка, PostgreSQL и HTTP прошли.
В браузере на наборе без анализа проверены десять маркеров/участников, выбор
героя, кнопки и клавиатура таймлайна, фильтр без результатов, перезагрузка ссылки,
командный режим без маркеров/таблиц/ретроспективного журнала. Заметка сохранена
через форму, найдена после перезагрузки, ссылка открыла тот же момент/героя.
В другой перспективе заметка не отображается.

Команды: `npm run test:match-explorer`, `npm run test:match-notes`,
`npm run test:explorer-web` (production web должен быть собран).

  разобран штатными worker/Kotlin/Clarity. Все десять участников и 30 значений
  K/D/A совпали с сохранённой сводкой источника.
