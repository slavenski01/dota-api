# Проверка профиля и истории матчей

Дата: 12 октября 2026 года. Задача: E01-T01. Статус: DONE.

OpenDota без API-ключа вернул выбранный профиль, историю и сводки пяти матчей. Во всех пяти найден ровно один участник с выбранным account_id; его данные согласованы с историей. Это подтверждает доступ к проверенной выборке, но не полноту всей истории, работу адаптера приложения или доступность файлов реплеев.

По решению пользователя публичная версия обезличена: ID, ники, ссылки на профиль/матчи, индивидуальная статистика и конкретные времена игр остаются только в локальных артефактах. Числа ниже описывают объём проверок, а не историю конкретных игр. Полный отчёт сохранён в `data/source-validation/2026-10-12-e01-t01/report-private.md`; папка исключена из Git.

## 1. Идентификация

Пользователь предоставил Steam-профиль. SteamID64 разобран через BigInt: public universe = 1, individual account type = 1, desktop instance = 1. Проверены преобразование в Dota account_id и обратное преобразование. Формула для этого типа аккаунта: `account_id = SteamID64 − 76561197960265728`. SteamID64 нельзя предварительно превращать в JavaScript Number; формулу нельзя без проверки применять к группам и произвольным числам. В контракте приложения ID остаются строками.

OpenDota `profile.account_id`, `profile.steamid` и `profile.profileurl` совпали с выбранным профилем. Steam Community XML подтвердил тот же SteamID64, `privacyState=public`, `visibilityState=3`. OpenDota вернул `fh_unavailable=false`; непустая история проверена отдельно.

Ники двух источников различались. Возможное объяснение — разная свежесть данных, но причина не установлена. Идентичность подтверждена по ID, не по нику. Открытость Steam-профиля и `fh_unavailable=false` не доказывают полноту истории Dota. `computed_mmr` не используется как точный MMR.

## 2. Реальные запросы и результаты

12 октября 2026 года сохранены 12 GET-ответов без ключей и авторизации; каждый завершился HTTP 200. База OpenDota: `https://api.opendota.com/api`. Идентификаторы в путях ниже — параметры, а не буквальные значения.

| Путь | Фактический результат |
| --- | --- |
| `/players/{account_id}` | Профиль с согласованными SteamID64/account_id |
| `/players/{account_id}/recentMatches` | 20 записей |
| `/players/{account_id}/matches?limit=5&offset=0&significant=0` | 5 записей |
| `/players/{account_id}/matches?limit=5&offset=5&significant=0` | 5 других записей |
| `/matches/{match_id}` — пять запросов | В каждой сводке 10 участников, один с выбранным account_id |
| `/heroes` | Справочник для сверки героев |
| `/api` относительно `https://api.opendota.com` | OpenAPI 3.0.3, версия API в info.version: 31.1.0 |
| Steam Community `/profiles/{steamid64}/?xml=1` | Публичный XML-профиль с совпавшим SteamID64 |

Первые две страницы содержат 10 уникальных match_id и в том же порядке совпадают с первыми 10 записями recentMatches. Это подтверждает работу limit/offset на данном снимке. Обновления истории между запросами могут сдвинуть offset; будущему адаптеру нужны дедупликация по match_id и сохранение параметров запроса.

В каждой из пяти сводок проверены точный запрошенный match_id, единственность выбранного участника и совпадение с историей по player_slot, hero_id, K/D/A, start_time, duration, radiant_win, game_mode и lobby_type. Результат игрока определяется по стороне и radiant_win. Это согласованность методов одного провайдера; независимая сверка через Steam Web API или клиент Dota не проводилась. Роль из героя/слота не выводилась.

Проверенная [схема OpenDota](https://api.opendota.com/api) документирует limit, offset, sort и significant; significant по умолчанию равен 1, в проверке явно использован 0 для включения нестандартных режимов. [Документация](https://docs.opendota.com/) задаёт ожидаемые поля, но не гарантирует их наличие в конкретном ответе. В заголовках наблюдались остатки минутной/суточной квоты; постоянные лимиты и поведение при HTTP 429 не проверялись.

## 3. Покрытие и ограничения

Во всех пяти сводках присутствуют итоговые K/D/A, last_hits, denies, GPM, XPM, урон героям и строениям, лечение, уровень, длительность и результат матча. Во всех пяти `od_data.has_api=true`, `has_gcdata=true`, `has_parsed=false`, `has_archive=false`. Поле version в сводках отсутствует, а в соответствующих записях истории равно null; эти состояния сохранены раздельно.

Отсутствуют поля teamfights, objectives, radiant_gold_adv и поля выбранного игрока kills_log, purchase_log, gold_t, xp_t. Это отсутствие подробных данных в ответах, а не отсутствие событий в игре. HTTP 200 и десять участников не подтверждают событийное покрытие. Выводы о причинах смертей, покупках, видимости и решениях по этим сводкам не делаются.

Во всех пяти ответах есть строковый replay_url. Файлы в E01-T01 не запрашивались; доступность ссылок, скачивание, распаковка и сверка match_id внутри `.dem` относятся к E01-T02.

| Ситуация | Результат проверки / граница вывода |
| --- | --- |
| Доступная история | 20 последних записей и две страницы по 5; полнота всей истории и её нижняя граница не исследованы |
| Пустая выдача | Не наблюдалась; успешный пустой массив сам по себе не доказывает отсутствие игр или приватность |
| Приватность | Для выбранного профиля public и fh_unavailable=false; скрытая история и анонимный участник не проверены |
| Ошибка API | В сохранённых запросах не наблюдалась; HTTP-ошибки, ошибки в теле, неверный формат и сетевой сбой должны отличаться от пустых данных. Сбой одного метода не означает отказ источника целиком |
| Ошибка локального доступа | Первая попытка curl из sandbox не соединилась с локальным прокси, HTTP 000; повтор с разрешённым сетевым доступом успешен. Это не HTTP-ошибка OpenDota |
| Steam Web API | Не потребовался; методы истории/сводки Steam и ключи в этой сессии не проверялись |

Исторические наблюдения о Steam HTTP 500 из [справочника skill](../.agents/skills/dota-match-analysis/references/session-observations.md) не выдаются за результаты текущей сессии.

## 4. Локальные доказательства и воспроизведение

В `data/source-validation/2026-10-12-e01-t01/` сохранены тела, заголовки, метаданные curl и manifest.json: URL, метод, HTTP-статус, HTTP Date, время сохранения, размер, длительность запроса и SHA-256 каждого из 12 тел. report-private.md содержит реальные идентификаторы, таблицу матчей, индивидуальные показатели и сокращённый пример ответа. Эти материалы исключены из Git и отсутствуют в новом клоне; исходники не заменены синтетическими fixtures.

Для повторения использовать пути из раздела 2 с выбранными ID. Сохранять новые ответы в отдельную локальную папку, записывать дату и параметры, проверять HTTP и содержимое, точный match_id и account_id участника. История может измениться. Ключи для проведённой проверки не понадобились.

Проверки над исходными JSON/XML подтвердили все 12 HTTP-статусов и SHA-256, идентификацию, страницы истории и данные пяти сводок. Критерии E01-T01 выполнены. Контракты данных 0.1.0 и NDJSON 1.0.0 не менялись; продуктовый адаптер и обработка ошибок в приложении ещё не реализованы.

Следующий шаг — E01-T02: получить 3–5 контрольных реплеев из локального списка кандидатов. Минимальный критерий — хотя бы один проверенный файл по цепочке профиль → матч → реплей.
