# Детерминированный анализ E06

`@dota/analysis`, версия правил `e06-v1`. Результат правила содержит ID/версию,
конфигурацию и SHA-256, якорь, включительное окно, требования к данным,
evidence-ссылки, факты и ограничения. Исходы `signal`, `no_signal`, `skipped`
различны: пропуск никогда не означает отсутствие события. Аналитический
контекст принимает проверку покрытия только от доверенного адаптера данных.

Метрики хранят формулу, исходные числа, единицу, evidence и причину неизвестности.
Реализованы смерти × 600 / длительность, (K+A) / убийства команды, преимущество
с позиции игрока, снимки временного ряда и накопительные приросты. Нулевой или
неизвестный знаменатель не даёт ноль. Отрицательное преимущество не обрезается.

Снимки на 300/600 секундах требуют подтверждённой игровой оси. Берётся точное
наблюдение либо последнее предыдущее не старше подтверждённого интервала;
фактическое время сохраняется. Конфликты и неизвестное последнее наблюдение
не заменяются удобным значением. Покупка не означает получение предмета.
Заработанное золото, текущее золото и стоимость имущества имеют разные имена.

Парсер E05 предоставляет итоговые счётчики, но не ряды добиваний/опыта на 5/10
минутах. Поддержка вычисления по подтверждённым рядам проверяется синтетическими
входами; наличие этой функции не подтверждает доступность рядов в реплее.
Метрики сравнений и ручных оценок относятся к E09/E07.

Проверки: `npm run test:metrics`, `npm run test:coverage`.

## Смерти

D01 проверяет включительное окно t−15…t+30 по всем десяти участникам; неполное
окно не сокращается. D02 ищет подтверждённую потерю башни/казарм своей команды
или Roshan, полученного противником, на t…t+90. Владелец и сторона результата
не взаимозаменяемы. Неизвестная сторона откладывает вывод; положительный факт
допускается из частичного журнала. Оба правила сохраняют ограничения интерпретации.
Окно просмотра может быть обрезано доступной записью и имеет явный флаг.
Проверки: `npm run test:death-rules` (5 групп граничных/конфликтных сценариев).
