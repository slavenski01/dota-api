# Dota API

Локальный MVP для самостоятельного изучения матчей Dota 2: история, скачивание
и импорт реплеев, разбор Kotlin/Clarity, карта всей игры, статистика десяти
игроков, события, графики HP/маны и собственные заметки.

**E00–E07, E12 и E10 завершены; M3 принят 13 октября 2026 года.** Реальный матч
прошёл весь путь, остановку worker, перезапуск сервисов и восстановление копии.
[Протокол приёмки](docs/mvp-acceptance.md) · [релизный чек-лист](docs/release-checklist.md).
Следующая итерация запланирована на 18 октября 2026 года: иконки всех героев E13,
плавный просмотр E14, AI-тренер E08 и совместный разбор с приёмкой E15.
E13 начат: локальный каталог 127 иконок готов; подключение к карте — следующий шаг.
Текущий MVP работает без LLM и его ключа.
Сравнения E09 и видео E11 остаются отложенными.

## Быстрый запуск

Нужны Git, Node.js **26.3.0**, Docker Engine с Compose v2+ и Buildx. PostgreSQL,
JVM и зависимости приложения собираются внутри контейнеров. Проверено на
Apple Silicon / Colima с 4 CPU и 8 GiB RAM. Установка Colima и подключение
Docker context описаны в [инструкции окружения](docs/local-operations.md).

```sh
git clone https://github.com/slavenski01/dota-api.git
cd dota-api
node scripts/local.mjs init
node scripts/local.mjs up
node scripts/local.mjs status
```

По умолчанию: [открыть профиль](http://127.0.0.1:3000/profile).
**В текущем рабочем окружении: [открыть сервис на порту 3002](http://127.0.0.1:3002/profile)** —
порт 3000 занят прежним процессом. `DOTA_PORT` хранится в `.env`.
Для установленной здесь Colima перед командами нужен
`export DOCKER_CONTEXT=colima-dota-api` в текущем терминале.

`init` создаёт случайный пароль БД и сохраняет существующие настройки. Миграции
применяются автоматически. Приложение доступно только на loopback; БД не
публикует порт. Web, worker и PostgreSQL должны показывать healthy:

```sh
curl --fail http://127.0.0.1:3002/api/ready  # замените порт своим
node scripts/local.mjs status
docker compose logs --tail=100 web worker migrate
```

`/api/health` проверяет только процесс web, `/api/ready` — БД, очередь и Storage.
У worker отдельный heartbeat. `node scripts/local.mjs stop` останавливает сервисы
с сохранением данных. Подробности отказов, прокси и портов — в
[local-operations.md](docs/local-operations.md).

## Как изучить матч

1. На `/profile` выберите тип **account ID** или **SteamID64**, введите ID и
   сохраните профиль. Обновите историю; даты фильтров задаются в UTC.
2. Откройте матч и нажмите «Загрузить и разобрать». Закрытие вкладки не отменяет
   работу; прогресс и результат сохраняются в БД.
3. Откройте «Исследовать всю игру». Выберите время, героя, тип события и участника.
   Событие переводит карту на свой момент. Автоматические эпизоды не обязательны.
4. Сохраните заметку или ссылку на момент. Они включают конкретный набор данных,
   время, героя и перспективу. После повторного разбора старые ссылки и заметки
   остаются связаны с прежним набором.

Если реплей недоступен, сохранённая статистика остаётся. В карточке можно
повторить запрос либо импортировать свой `.dem`; формат, размер, матч и участник
проверяются до публикации. Уже сохранённый реплей можно скачать. При 429
дождитесь Retry-After; повторные нажатия не обходят лимит. Пустая история не
доказывает отсутствие матчей: источник может иметь ограниченный доступ.

OpenDota даёт профиль/историю/метаданные, Valve CDN — реплей. Ключ не обязателен;
при наличии укажите `OPENDOTA_API_KEY` в `.env`, затем повторите `local.mjs up`.
`DOTA_HTTP_PROXY` задаёт исходящий прокси, доступный **из контейнеров**. Серверные
ключи нельзя помещать в `NEXT_PUBLIC_*`. Steam Web API в этом маршруте не нужен.

## Границы данных

«Полный просмотр» означает все доступные проверенные данные. Неизвестные поля
не заменяются нулями, пропуски не заполняются. Ретроспектива показывает сведения
из полного реплея и не доказывает, что игрок знал их в момент решения.

- Подложка **7.40 приблизительная**; в контрольном реплее отдельные ориентиры
  смещены до 9% ширины карты. Точный рельеф, проходимость и туман войны не восстановлены.
- Командная видимость и cooldown/canUse пока неизвестны; в командном режиме
  неподтверждённые позиции и события скрыты.
- Есть итоговая статистика и наблюдения HP/маны. Временных рядов золота, опыта
  и добиваний нет; покупка предмета не означает доставку герою.
- Детерминированные кандидаты эпизодов и ручные оценки доступны, но не являются
  автоматическим доказательством ошибки. Правила без нужного покрытия пропускаются.
- Поддержка произвольных будущих реплеев, полнота истории и вечная доступность
  CDN не обещаются. Публичный доступ, отдельные аккаунты и расписания вне MVP.

Подробности: [нормализация](docs/normalization.md),
[карта](docs/map-calibration.md), [просмотр и заметки](docs/match-explorer.md).

## Обновление и резервная копия

База и очередь находятся в volume `dota-api_postgres`, артефакты —
`dota-api_storage`. `.env` и данные исключены из Git и контекста сборки.
Не используйте `docker compose down --volumes` для обычной остановки.

```sh
mkdir -p data/backups
node scripts/local.mjs backup data/backups/before-update
node scripts/local.mjs verify data/backups/before-update
git pull --ff-only
node scripts/local.mjs up
```

Имя каталога каждой копии должно быть новым. Копирование кратко останавливает
web/worker, сохраняет согласованные dump, Storage и образ, затем запускает
ранее работающие сервисы. После обновления проверьте готовность, прежний матч
и заметку. Восстановление выполняется **в новый проект**:

```sh
node scripts/local.mjs restore data/backups/before-update dota-restored 3001
```

Откройте восстановленный матч и заметку на 3001. Команда проверяет хеши и
отказывается перезаписывать существующие volumes. Храните копию отдельно от
рабочего диска, а `.env` — отдельно от копии. Полная процедура, требования к
свободному месту и откат схемы: [эксплуатация](docs/local-operations.md).

## Разработка и проверки

Для разработки вне контейнеров дополнительно нужны npm **11.16.0**, JDK **21**,
`bzip2` и PostgreSQL 18. Задайте `DATABASE_URL` для своей БД и `STORAGE_ROOT`
в `.env`: внутренний адрес `db` из Compose недоступен с хоста. SQL-миграции
применяются через `npm run db:migrate`. Dev web и worker запускаются отдельно
командами `npm run dev:web` и `npm run dev:worker` после сборки общих пакетов.

```sh
npm ci
npm run build
npm run typecheck
npm run test:contracts
npm run smoke
npm run test:jobs
npm run test:workflow
npm run test:storage
npm run test:match-explorer
npm run test:match-notes
npm run test:explorer-web
npm run test:replay-web
npm run test:backup
node scripts/sync-task-board.mjs --check
```

Интеграционные тесты автоматически запускают отдельную временную PostgreSQL
от обычного пользователя, не используют рабочую БД. Для `replay-web` реальный
подсценарий требует локального E01 manifest; без него явно пропускается.
`npm run test:ops` требует готового Docker-образа и проверяет изолированные
Compose-проекты с последующей очисткой только их данных. Live-приёмка через
`scripts/acceptance.mjs` имеет отдельные условия в [протоколе](docs/mvp-acceptance.md).

| Компонент | Версия |
| --- | --- |
| Node / npm | 26.3.0 / 11.16.0 |
| Next.js / React / TypeScript | 16.4.0 / 19.3.0 / 5.9.3 |
| JRE в контейнере / Kotlin / Gradle | Temurin 21.0.12.1 / 2.4.20 / 9.5.1 |
| Clarity / protobuf | 5.0.1 / 7.1 |
| PostgreSQL / pg-boss | 18.6 / 12.37.1 |
| Контракт / NDJSON | 0.1.0 / 1.0.0 |

Прямые зависимости, lockfiles и digest базовых образов закреплены. Обновляйте
их явно и повторяйте соответствующие проверки. `build` собирает workspaces,
production web и Kotlin CLI; Gradle Wrapper включён в репозиторий.
